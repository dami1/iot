Por que a forma do pedido importa

Usar IA para escrever código não é delegar o pensamento — é organizá-lo. O risco real de um prompt mal formulado não é a IA "errar": é gerar um código que funciona mas que ninguém entende. Código que não se entende não se consegue depurar, adaptar nem defender. Para quem trabalha com experiência do usuário, isso é o oposto de ter autoria sobre o projeto.

Princípio
O prompt é o algoritmo verbalizado

As mesmas sete etapas de estruturação de algoritmo da primeira aula — definir o objetivo, mapear entradas e saídas, decompor em partes, escrever o fluxo em linguagem natural, identificar loops e condições, implementar por partes, refinar — são exatamente o que um bom prompt contém.

Quem sabe estruturar um algoritmo já sabe estruturar um prompt. O prompt vago falha porque pula a decomposição; o prompt bom é a decomposição escrita em palavras.

Anatomia de um bom prompt

  • Contexto técnico — qual linguagem, qual ambiente, qual versão. "Em p5.js, no editor online" é diferente de "em JavaScript".
  • Objetivo específico — o que o sistema faz, descrito sem ambiguidade.
  • Bibliotecas e dependências — o que incluir, e em que versão. Especificar a versão evita que a IA misture sintaxes de APIs diferentes.
  • Estrutura de dados — pedir classes, atributos e métodos com nomes específicos faz a IA gerar código que você reconhece.
  • Lógica em linguagem natural — descrever os loops e condicionais em português; a IA traduz, mas a lógica é sua.
  • Decisões estéticas — a parte que a IA não inventa sozinha. É onde o design entra.
  • Pedido de explicação — pedir que explique partes específicas transforma o uso em aprendizado.

Estudo de caso — partículas que saem da boca

O objetivo bruto: "partículas que saem da boca quando ela abre, e trocam de cor de acordo com o volume". Uma frase de intenção, como a prospecção de projeto. O trabalho é transformar isso em especificação — passando pelas mesmas etapas de decomposição de um algoritmo.

Prompt fraco
"faz partículas que saem da boca e mudam de cor com o som"
Prompt estruturado
contexto + biblioteca + versão + classe especificada + loops descritos + mapeamento sensorial + decisões estéticas + pedido de explicação

O primeiro gera algo provavelmente quebrado ou genérico. O segundo gera código que se entende, se depura e se adapta — porque o sistema inteiro foi pensado antes de pedir.

Decompondo antes de escrever

  • Entradas: câmera (detectar a boca e medir abertura) + microfone (medir volume)
  • Processamento: detecção facial → calcular abertura da boca → emitir partículas; leitura de volume → definir cor
  • Saída: partículas animadas na tela
  • Estrutura: uma classe para a partícula, um array para guardar várias

O prompt completo montado

O resultado de passar a intenção por todas as etapas — como o aluno entregaria à IA:

Quero criar um sketch em p5.js onde partículas saem da boca de uma pessoa quando ela abre a boca, e a cor das partículas muda de acordo com o volume do microfone.
Ambiente e bibliotecas: vou rodar no editor online do p5.js. Use a biblioteca ml5.js para detecção facial com ml5.faceMesh() (API atual do ml5 v1, com detectStart) e a p5.sound para captar o microfone. Diga também quais tags <script> incluir no index.html e em que ordem.
Estrutura — classe Particula: crie uma classe Particula com:
  • atributos: posição (x, y), velocidade (vx, vy), cor, tamanho, tempo de vida
  • método update() que move a partícula, aplica leve gravidade e diminui o tempo de vida
  • método display() que desenha com transparência proporcional ao tempo de vida (fade out)
  • método estaMorta() que retorna true quando a vida chega a zero
Lógica no draw() — loops e condicionais:
  • rode o faceMesh para detectar o rosto
  • calcule a abertura da boca pela distância entre o lábio superior e o inferior
  • se a abertura passar de um limiar, crie várias partículas na posição da boca e adicione a um array — quantidade proporcional à abertura
  • use um loop para percorrer o array, chamando update() e display()
  • remova as partículas mortas usando um loop reverso, para não pular índices
Mapeamento do volume para a cor: capte o volume com getLevel() (0 a 1). No momento em que cada partícula nasce, defina sua cor a partir do volume: baixo gera tons frios (azul), alto gera tons quentes (laranja). Use o modo HSB para a transição de matiz.
Estética:
  • fundo escuro para as cores brilharem
  • tamanho com leve variação aleatória entre partículas
  • velocidade inicial espalhada num leque a partir da boca
  • fade out suave acompanhando o tempo de vida
Depois de escrever o código, me explique o cálculo da abertura da boca e o loop reverso de remoção — quero entender essas duas partes para adaptar depois.
O que observar: o prompt nomeia a estratégia (loop reverso, distância entre pontos) mas deixa a sintaxe para a IA. Você controla a arquitetura; a IA preenche o como. E a última frase — pedir explicação de duas partes específicas — é o que transforma delegação em aprendizado.
Atividade: partindo de um objetivo próprio, cada aluno escreve o prompt decomposto seguindo os sete blocos. Testar, ler criticamente o resultado, e iterar descrevendo o sintoma do erro ("o círculo pisca", "dá undefined na linha X") em vez de pedir "conserta".
Síntese: o prompt não é onde você delega o pensamento — é onde você o organiza.

O celular como interface

O smartphone é uma das interfaces mais ricas em sensores que existe — tela multitoque, acelerômetro, giroscópio, microfone, câmera, GPS, bússola — e cabe no bolso. Para o campo da experiência do usuário, é um território fértil: o público já carrega o dispositivo, já sabe operá-lo, e ele pode virar instrumento, controle ou sensor de uma instalação.

A boa notícia: para a maioria dos casos em p5.js, não é preciso biblioteca nenhuma. O p5.js já acessa o touch e os sensores de movimento nativamente. Bibliotecas externas entram só quando se quer gestos compostos prontos.

Sobre o Hammer.js: por anos foi a referência para gestos touch, mas está sem manutenção desde 2016. Para gestos compostos hoje, as alternativas mantidas são Interact.js (manipulação de elementos, pinça, rotação) e @use-gesture. Mas para interação baseada em canvas — o caso do p5.js — o touch nativo costuma ser mais direto e transparente.
Como testar: os exemplos abaixo rodam embarcados nesta página. Para sentir os sensores de verdade, abrir esta aula no navegador do celular e usar o botão de tela cheia em cada exemplo. Câmera e sensores de movimento pedem permissão na primeira vez.

Touch nativo e multitouch

O array touches[] traz todos os dedos na tela ao mesmo tempo — cada um com .x, .y e .id. Multitouch é simplesmente percorrer esse array. As funções de evento touchStarted(), touchMoved() e touchEnded() são as equivalentes touch das de mouse.

Detalhe essencial no celular: retornar false dentro de touchMoved() impede o navegador de rolar a página ou dar zoom ao tocar o canvas. Sem isso, qualquer arrasto atrapalha a interação.

Exemplo 1 — pontos multitoque

Cada dedo desenha um círculo. Vários dedos ao mesmo tempo, vários círculos.

ver código · multitouch.js
let cores = [];
function setup() {
  createCanvas(windowWidth, windowHeight);
  background(26, 26, 24);
  noStroke();
}
function draw() {
  // leve fade do fundo para deixar rastro suave
  fill(26, 26, 24, 25);
  rect(0, 0, width, height);
  for (let i = 0; i < touches.length; i++) {
    let t = touches[i];
    fill(200, 77, 10, 180);
    circle(t.x, t.y, 70);
    fill(255);
    textSize(14);
    textAlign(CENTER, CENTER);
    text(i + 1, t.x, t.y);
  }
  // contador de dedos
  fill(255);
  textSize(16);
  textAlign(LEFT, TOP);
  text(touches.length + " toque(s)", 16, 16);
}
function touchMoved() { return false; }
function windowResized() { resizeCanvas(windowWidth, windowHeight); }

Atividade: mudar a cor de cada toque conforme o índice no array, ou desenhar linhas conectando todos os dedos ativos. O array touches[] tem tudo que é preciso.

Exemplo 2 — pinça feita à mão

Medir a distância entre dois dedos é a base de um gesto de pinça-zoom — sem nenhuma biblioteca. É o mesmo raciocínio do cálculo de abertura da boca: distância entre dois pontos.

ver código · pinca.js
function setup() {
  createCanvas(windowWidth, windowHeight);
}
function draw() {
  background(26, 26, 24);
  if (touches.length >= 2) {
    let a = touches[0];
    let b = touches[1];
    let d = dist(a.x, a.y, b.x, b.y);
    // linha entre os dedos
    stroke(200, 77, 10);
    strokeWeight(4);
    line(a.x, a.y, b.x, b.y);
    // círculo cujo tamanho é a distância
    noStroke();
    fill(200, 77, 10, 80);
    circle((a.x+b.x)/2, (a.y+b.y)/2, d);
    // valor
    fill(255);
    textSize(22);
    textAlign(CENTER, CENTER);
    text(round(d) + " px", (a.x+b.x)/2, (a.y+b.y)/2);
  } else {
    fill(150);
    textSize(18);
    textAlign(CENTER, CENTER);
    text("toque com dois dedos", width/2, height/2);
  }
}
function touchMoved() { return false; }
function windowResized() { resizeCanvas(windowWidth, windowHeight); }

Sensores de movimento — acelerômetro e giroscópio

O p5.js expõe os sensores de movimento como variáveis globais: rotationX/Y/Z para orientação (giroscópio) e accelerationX/Y/Z para aceleração linear. Não precisa de biblioteca — mas precisa de permissão.

Conceito
Permissão de sensores — o mesmo padrão do botão serial

Desde o iOS 13, acessar acelerômetro e giroscópio exige permissão explícita do usuário via DeviceOrientationEvent.requestPermission(), acionada por um clique. É exatamente o mesmo padrão de segurança do botão de conexão serial da aula 5: navegadores protegem hardware sensível atrás de um gesto do usuário.

No Android a permissão costuma ser concedida direto; o código abaixo trata os dois casos.

Exemplo 3 — bolha de nível

A inclinação do aparelho move uma bolha pela tela, como um nível de bolha físico. Toque em "ativar sensores" e incline o celular.

ver código · acelerometro.js
let permissaoOk = false;
let btn;
function setup() {
  createCanvas(windowWidth, windowHeight);
  btn = createButton("ativar sensores");
  btn.position(16, 16);
  btn.style("font-size", "16px");
  btn.style("padding", "8px 14px");
  btn.mousePressed(pedirPermissao);
}
function pedirPermissao() {
  if (typeof DeviceOrientationEvent !== "undefined" &&
      typeof DeviceOrientationEvent.requestPermission === "function") {
    DeviceOrientationEvent.requestPermission().then(function(res) {
      if (res === "granted") { permissaoOk = true; btn.hide(); }
    });
  } else {
    permissaoOk = true; btn.hide();
  }
}
function draw() {
  background(26, 26, 24);
  if (!permissaoOk) {
    fill(150); textSize(16); textAlign(CENTER, CENTER);
    text("toque em 'ativar sensores'", width/2, height/2 + 40);
    return;
  }
  // inclinação move a bolha pela tela
  let x = map(rotationY, -45, 45, 0, width, true);
  let y = map(rotationX, -45, 45, 0, height, true);
  fill(200, 77, 10);
  noStroke();
  circle(x, y, 90);
  fill(255); textSize(15); textAlign(LEFT, TOP);
  text("rotationX: " + round(rotationX), 16, 70);
  text("rotationY: " + round(rotationY), 16, 92);
}
function windowResized() { resizeCanvas(windowWidth, windowHeight); }
acelerometro.js · bolha de nível
Variações: accelerationX/Y/Z para aceleração linear (movimento brusco), e rotationZ para a bússola. Uma bolinha que rola com a gravidade é o exemplo canônico — imediato de entender.

Exemplo 4 — detecção de chacoalhada

O p5.js facilita a detecção de movimento brusco com setMoveThreshold() e a função de evento deviceMoved(). Chacoalhe o celular para trocar a cor.

ver código · shake.js
let cor;
function setup() {
  createCanvas(windowWidth, windowHeight);
  setMoveThreshold(30);
  cor = color(26, 26, 24);
}
function draw() {
  background(cor);
  fill(255); textSize(18); textAlign(CENTER, CENTER);
  text("chacoalhe o aparelho", width/2, height/2);
}
function deviceMoved() {
  cor = color(random(120,255), random(40,120), random(10,60));
}
function windowResized() { resizeCanvas(windowWidth, windowHeight); }

Bibliotecas de gesto e o celular em rede

Quando uma biblioteca vale a pena

Para gestos compostos prontos — pinça, rotação de dois dedos, swipe direcional — uma biblioteca evita reimplementar a lógica. A opção atual mais consolidada é o Interact.js.

index.html + uso · Interact.js
<script src="https://cdn.jsdelivr.net/npm/interactjs/dist/interact.min.js"></script>

interact('.elemento').gesturable({
  onmove: function (event) {
    // event.scale = fator de pinça (zoom)
    // event.angle = rotação em graus
    console.log(event.scale, event.angle);
  }
});
Decisão de design: o Interact.js trabalha sobre elementos do DOM, não sobre o canvas p5. Se a interface é toda canvas, o touch nativo é mais direto. Se há elementos HTML (botões, imagens, divs), a biblioteca brilha. Escolher não usar uma biblioteca é também uma decisão de design — nem todo problema precisa de uma dependência a mais.

O celular como interface de instalação

Fechando o arco do curso: o smartphone vira o controlador remoto de um sistema audiovisual. Como o navegador não envia OSC/UDP diretamente, a ponte usual é WebSocket — o celular envia os dados dos sensores para um servidor na rede, que os retransmite.

sketch.js · enviando sensores via WebSocket (conceitual)
let socket;

function setup() {
  createCanvas(windowWidth, windowHeight);
  socket = new WebSocket('ws://192.168.0.10:8080');
}

function draw() {
  if (socket.readyState === WebSocket.OPEN) {
    let dados = JSON.stringify({
      x: rotationX, y: rotationY, toques: touches.length
    });
    socket.send(dados);
  }
}
Gancho para a próxima aula: o servidor WebSocket→OSC é uma peça extra (Node.js, ou Node-RED que veremos no IoT). Por isso o MobMuPlat é elegante: ele fala OSC nativamente do celular para o Pure Data, sem montar essa ponte. É o caminho que exploraremos a seguir.
Atividade final: em duplas, um celular controlando um sketch p5.js ou patch PD em outra tela. Qual sensor faz sentido para qual parâmetro? Inclinar para navegar, chacoalhar para disparar, tocar para criar — cada gesto carrega uma expressividade diferente.
