Protocolos de comunicação — MIDI, Serial e OSC

Um protocolo de comunicação é um acordo sobre como dois sistemas trocam dados: o formato das mensagens, a velocidade, a ordem dos bytes. Em sistemas interativos, três protocolos cobrem praticamente todos os cenários de conexão entre hardware, software e rede.

Serial
RS-232, anos 1960
  • Comunicação ponto a ponto via cabo (USB)
  • Bytes em sequência, um a um
  • Velocidade em baud: 9600, 115200…
  • Sem endereçamento — um emissor, um receptor
  • É como o Arduino fala com o computador
MIDI
1983
  • Padrão da indústria musical
  • Mensagens: note on/off, control change, pitch bend
  • Valores de 0 a 127 (7 bits)
  • 16 canais por porta
  • Universal: qualquer DAW, sintetizador ou controlador entende
OSC
Open Sound Control, 1997
  • Sucessor moderno do MIDI, via rede (UDP/IP)
  • Endereços legíveis: /sensor/luz
  • Valores de alta resolução: float, int, string
  • Funciona por WiFi, Ethernet, localhost
  • Padrão em PD, Max, TouchDesigner, Resolume

Quando usar cada um

  • Serial — quando há um cabo USB entre o microcontrolador e o computador. Simples, confiável, baixa latência. Limitação: distância do cabo e um dispositivo por porta.
  • MIDI — quando o destino é musical: controlar um sintetizador, uma DAW, um plugin. A resolução de 7 bits (0–127) é limitada, mas a compatibilidade é universal.
  • OSC — quando os dispositivos estão em rede: múltiplos computadores, smartphones, ESP32 via WiFi. Resolução ilimitada, endereçamento legível, múltiplos destinos. É o protocolo central das próximas aulas.

OSC a fundo — e implementação no Pure Data

OSC (Open Sound Control) foi criado no CNMAT da UC Berkeley como resposta às limitações do MIDI: resolução baixa, endereçamento rígido e dependência de cabo dedicado. O OSC trafega por redes comuns — a mesma infraestrutura de internet — usando geralmente o protocolo UDP.

Anatomia
A mensagem OSC

Toda mensagem OSC tem duas partes: um endereço — um caminho hierárquico legível, como uma URL — e um ou mais argumentos — os valores transmitidos, que podem ser float, int, string ou blob.

O endereçamento hierárquico é a grande elegância do protocolo: a estrutura do endereço documenta o próprio sistema.

/sensor/luz 0.73 ← um float de alta resolução
/sensor/distancia 142.5 ← centímetros, sem perda de precisão
/corpo/mao/direita/x 0.41 ← hierarquia descreve o sistema
/synth/osc1/freq 440.0 ← controle de parâmetro remoto
/cena/trocar "abertura" ← strings também trafegam
Rede
IP e porta — o endereço da máquina

OSC viaja por UDP, o protocolo de datagramas da internet. Para enviar uma mensagem é preciso saber dois números: o IP da máquina de destino (ex: 192.168.0.15, ou 127.0.0.1 para a própria máquina) e a porta em que o receptor está escutando (ex: 8000).

UDP não confirma a entrega — mensagens podem se perder. Para controle em tempo real isso é uma vantagem: melhor perder um valor antigo do que travar o fluxo esperando confirmação.

OSC no Pure Data

O PD Vanilla inclui os objetos de OSC nativamente desde a versão 0.46 — sem bibliotecas externas.

[netreceive -u -b 8000]
Abre a porta UDP 8000 para receber dados. As flags: -u = UDP, -b = binário.
[oscparse]
Decodifica o pacote binário OSC em mensagens PD — endereço seguido dos argumentos.
[route sensor]
Filtra mensagens pelo primeiro elemento do endereço. [route sensor] → [route luz distancia] separa cada sensor em uma saída.
[oscformat sensor luz]
Codifica o caminho inverso: monta a mensagem OSC /sensor/luz com os argumentos recebidos.
[netsend -u -b]
Envia o pacote pela rede. Recebe mensagem connect 127.0.0.1 8000 para definir o destino.

Patch receptor — passo a passo

1
Criar [netreceive -u -b 8000] — o PD passa a escutar a porta 8000 em UDP
2
Conectar a saída ao [oscparse] — pacotes binários viram mensagens legíveis
3
Conectar ao [route sensor] e depois [route luz distancia] — cada endereço sai por uma saída diferente
4
Conectar cada saída a uma caixa numérica — os valores chegam em tempo real, prontos para mapear a qualquer parâmetro
5
Teste: em outro patch (ou outra máquina da sala), montar o caminho de envio: [oscformat sensor luz] → [netsend -u -b] com [connect 127.0.0.1 8000(. Enviar valores de um slider e ver chegando no receptor.
Atividade: em duplas, um aluno envia OSC do seu computador para o computador do colega usando o IP da rede local da sala. Um slider em uma máquina controlando a frequência de um oscilador em outra — a primeira experiência de instalação em rede do curso.

Revisão — Arduino

Retomada rápida dos conceitos da aula 3 antes da integração com o p5.js.

  • setup() e loop() — configuração única e ciclo contínuo. A mesma estrutura do p5.js.
  • analogRead(A0) — lê tensão de 0 a 5V no pino analógico, retorna 0 a 1023.
  • Serial.begin(115200) — inicia a comunicação serial. A velocidade (baud rate) precisa ser idêntica nos dois lados da conexão.
  • Serial.print() / Serial.println() — envia dados pela serial. O println adiciona quebra de linha \n ao final — o delimitador que o receptor usa para saber onde a mensagem termina.
  • Protoboard — barramentos de alimentação nas bordas, colunas de 5 furos conectados no centro. Potenciômetro: extremos em 5V e GND, centro no pino analógico.
Verificação rápida: antes de seguir, cada aluno sobe um sketch que imprime o valor de A0 na serial e confirma no Serial Monitor (Tools → Serial Monitor, baud 115200) que os valores variam ao girar o potenciômetro. Fechar o Serial Monitor depois do teste — a porta não pode estar ocupada quando o navegador for conectar.

Arduino + p5.js — um sensor analógico

A biblioteca p5.webserial.js conecta o p5.js diretamente à porta serial do Arduino usando a Web Serial API do navegador — sem software intermediário. Funciona no Chrome e no Edge; o Firefox e o Safari não suportam Web Serial.

Conceito
Por que o botão de conectar

Por segurança, o navegador só permite acesso à porta serial após um gesto explícito do usuário — um clique. Por isso todo sketch com Web Serial tem um botão de conexão: o port.open() precisa ser chamado dentro de um evento de interação, nunca direto no setup().

Arduino — um sensor

sketch_um_sensor.ino · potenciômetro no A0
void setup() {
  Serial.begin(115200);
}

void loop() {
  int pot = analogRead(A0);
  Serial.println(pot); // envia "512\n"
  delay(20); // ~50 leituras por segundo
}

p5.js — recebendo o valor

sketch.js · um sensor controlando o diâmetro de um círculo
let port;
let pot = 0;

function setup() {
  createCanvas(400, 400);
  port = createSerial();
  let btn = createButton('conectar arduino');
  btn.mousePressed(() => port.open(115200));
}

function draw() {
  background(220);
  
  // lê todas as linhas disponíveis, guarda só a última completa
  let str = port.readUntil("\n");
  let ultimaLinha = "";
  while (str.length > 0) {
    ultimaLinha = str;
    str = port.readUntil("\n");
  }
  
  if (ultimaLinha.length > 0) {
    pot = int(trim(ultimaLinha));
  }
  
  // mapeia 0–1023 para o diâmetro
  let diametro = map(pot, 0, 1023, 10, 300);
  fill(200, 77, 10);
  noStroke();
  circle(width / 2, height / 2, diametro);
}
O loop de leitura importa: o Arduino envia ~50 valores por segundo, mas o draw() roda 60 vezes por segundo — nem sempre em sincronia. Se o sketch ler apenas uma linha por frame, as linhas não lidas acumulam no buffer e o círculo responde com atraso crescente. O laço while drena o buffer inteiro e usa só a última linha completa — o valor mais recente, sem lag.

Três sensores simultâneos

Para enviar múltiplos sensores pela mesma porta serial, o padrão é o CSV por linha: os valores separados por vírgula, a linha fechada com \n. O receptor divide a linha pelas vírgulas e distribui os valores.

512,847,103\n ← pot, LDR, pot2 — uma leitura completa por linha

Arduino — três sensores

sketch_tres_sensores.ino · potenciômetro (A0), LDR (A1), pot2 (A2)
// Três sensores: potenciômetro (A0), LDR (A1), outro pot (A2)
// Formato enviado: "512,847,103\n"

void setup() {
  Serial.begin(115200);
}

void loop() {
  int pot = analogRead(A0);
  int ldr = analogRead(A1);
  int pot2 = analogRead(A2);

  Serial.print(pot);
  Serial.print(",");
  Serial.print(ldr);
  Serial.print(",");
  Serial.println(pot2); // println só no último, fecha a linha com \n
  delay(20);
}

p5.js — recebendo e distribuindo os três valores

sketch.js · cada sensor controla uma propriedade diferente
let port;
let pot = 0, ldr = 0, pot2 = 0;

function setup() {
  createCanvas(400, 400);
  port = createSerial();
  let btn = createButton('conectar arduino');
  btn.mousePressed(() => port.open(115200));
}

function draw() {
  background(220);
  
  // lê TODAS as linhas disponíveis, guarda só a última completa
  let str = port.readUntil("\n");
  let ultimaLinha = "";
  while (str.length > 0) {
    ultimaLinha = str;
    str = port.readUntil("\n");
  }
  
  if (ultimaLinha.length > 0) {
    let valores = split(trim(ultimaLinha), ",");
    if (valores.length == 3) {
      pot  = int(valores[0]);
      ldr  = int(valores[1]);
      pot2 = int(valores[2]);
    }
  }
  
  // cada sensor controla uma propriedade diferente
  let diametro = map(pot, 0, 1023, 10, 300);
  let cinza    = map(ldr, 0, 1023, 0, 255);
  let posX     = map(pot2, 0, 1023, 0, width);
  
  fill(cinza);
  circle(posX, height / 2, diametro);
}

Anatomia do código — as funções chave

createSerial()
Cria o objeto de porta serial do p5.webserial. Não abre a conexão — só prepara.
port.open(115200)
Abre o diálogo do navegador para o usuário escolher a porta. O baud rate precisa ser o mesmo do Serial.begin() no Arduino.
port.readUntil("\n")
Lê do buffer até encontrar a quebra de linha. Retorna string vazia se não houver linha completa disponível.
split(str, ",")
Divide a string pelas vírgulas, retorna array: "512,847,103" → ["512","847","103"].
trim(str)
Remove espaços e caracteres invisíveis (como \r) das pontas da string — essencial antes de converter para número.
int(str)
Converte a string em número inteiro. "512" → 512.
valores.length == 3
Validação: só usa a linha se ela tiver exatamente 3 valores — protege contra linhas truncadas na conexão.
Atividade final: substituir o círculo por uma composição própria — cada sensor controlando uma propriedade visual diferente (cor, rotação, quantidade de elementos, velocidade de animação). A pergunta de projeto: qual gesto físico faz sentido para cada parâmetro? Girar um potenciômetro e cobrir um LDR são ações expressivamente diferentes.
