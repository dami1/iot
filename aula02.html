Revisão — Pure Data

Retomada rápida dos conceitos da aula anterior antes de avançar para os novos tópicos.

Objetos fundamentais revisados

[osc~]
Oscilador senoidal. Recebe frequência em Hz na entrada, gera sinal de áudio contínuo na saída.
[*~ 0.5]
Multiplicador de sinal — controla amplitude. O argumento é o fator; 0.5 = metade do volume.
[dac~]
Digital-to-analog converter — saída de áudio do sistema. Duas entradas: canal esquerdo e direito.
[number] / [hslider]
Interfaces de controle em tempo real. Atributos expostos como parâmetros manipuláveis pelo usuário.
[toggle]
Liga e desliga — envia 1 ou 0. Útil para ativar e desativar partes do patch sem interromper o DSP.
[bang]
Impulso sem valor — sinaliza "execute agora". Dispara mensagens e reinicia estados.
[print]
Imprime o valor recebido no console do PD. Ferramenta essencial para inspecionar o fluxo de dados e encontrar erros.
[metro 500]
Metrônomo — envia bangs em intervalos regulares. O argumento é o intervalo em milissegundos.
Atividade: cada aluno abre o patch da aula anterior. Adicionar um [metro] para automatizar a mudança de frequência e um [print] para inspecionar os valores — sem tocar no restante do patch.

Instalação de bibliotecas externas

O Pure Data Vanilla tem uma coleção de objetos nativos, mas seu ecossistema real está nas bibliotecas externas — conjuntos de objetos desenvolvidos pela comunidade que ampliam radicalmente as possibilidades do ambiente.

Bibliotecas do curso

Cyclone
Conjunto de objetos compatíveis com Max/MSP. Traz operadores matemáticos, filtros e utilitários que não existem no PD nativo — essencial para síntese e processamento de sinal mais sofisticado.
GitHub ↗
Pduino
Comunicação entre Pure Data e Arduino via protocolo Firmata. Permite ler sensores e controlar pinos do Arduino diretamente de dentro de um patch PD.
GitHub ↗
GEM
Graphics Environment for Multimedia — renderização OpenGL em tempo real dentro do PD. Formas 3D, texturas, shaders e vídeo controlados pelo mesmo patch de áudio.
gem.iem.at ↗

Como instalar — Deken (gerenciador nativo do PD)

1
No PD, abrir o gerenciador de pacotes: Help → Find Externals
2
Buscar cyclone — selecionar a versão mais recente e clicar em Install
3
Repetir para pduino e GEM
4
Reiniciar o PD após cada instalação — confirmar no console que a biblioteca foi carregada sem erros
5
Para carregar uma biblioteca no patch: [declare -lib cyclone] no início do patch, ou configurar em Edit → Preferences → Startup para carregamento automático
Atenção GEM: o GEM pode não estar disponível via Deken em todas as plataformas. Em caso de falha, instalar manualmente copiando a pasta da biblioteca para o diretório de externals do PD — geralmente ~/Documents/Pd/externals/ no Mac e %AppData%\Pd\externals\ no Windows.

Interfaces do computador — mouse, teclado e microfone

Antes de conectar hardware externo, o próprio computador oferece três entradas de dados em tempo real que já permitem construir sistemas interativos completos: o mouse, o teclado e o microfone.

Mouse

[mousestate]
Retorna posição X e Y do cursor, além do estado dos botões. Não precisa de biblioteca externa.
[expr $f1 / 1920]
Normaliza o valor de X (0 a resolução) para a faixa 0–1 — padrão para mapear para qualquer parâmetro.
1
Criar [mousestate] e conectar as saídas a caixas numéricas — observar os valores mudando ao mover o mouse
2
Normalizar X com [/ 1920] e mapear para frequência: [* 800] + [+ 200] — resultado: 200 a 1000 Hz conforme a posição horizontal
3
Conectar o resultado ao inlet de frequência do [osc~] do patch anterior

Teclado

[key]
Retorna o código ASCII da tecla pressionada. Ativo enquanto o patch estiver em foco.
[keyup]
Retorna o código ASCII da tecla solta. Usado em conjunto com [key] para detectar duração do pressionamento.
[keyname]
Retorna o nome legível da tecla (ex: space, Return) em vez do código numérico.
1
Criar [key] e conectar a um [print] — pressionar teclas e observar os códigos ASCII no console
2
Usar [select 32] para detectar a barra de espaço (ASCII 32) e conectar ao [toggle] que liga o oscilador
3
Mapear as teclas numéricas 1–5 (ASCII 49–53) para frequências predefinidas usando [select 49 50 51 52 53]

Microfone

[adc~]
Analog-to-digital converter — entrada de áudio do sistema. Saída esquerda e direita em sinal contínuo ~.
[env~ 1024]
Envelope follower — converte sinal de áudio em valor de amplitude em dB. O argumento é o tamanho da janela de análise.
[mtof] / [ftom]
Converte MIDI para Hz e vice-versa. Útil para mapear amplitude para altura de nota de forma musical.
1
Criar [adc~] e conectar ao [env~ 1024] — observar os valores de amplitude em dB no número conectado à saída
2
Normalizar para 0–1: [/ 100] — amplitude do microfone controlando o volume do oscilador via [*~ ]
3
Atividade: combinar mouse (frequência), teclado (on/off) e microfone (volume) em um único patch

Síntese visual com GEM

O GEM (Graphics Environment for Multimedia) é uma biblioteca que adiciona ao PD um pipeline de renderização OpenGL em tempo real. O mesmo patch que gera som pode controlar formas, cores e movimento em uma janela gráfica separada.

Conceito
Cadeia de renderização no GEM

O GEM funciona em cadeia: um objeto [gemwin] cria a janela, [gemhead] inicia o pipeline de renderização, e objetos de geometria como [sphere], [rectangle] ou [circle] são conectados abaixo. Atributos visuais — cor, posição, rotação, escala — chegam aos objetos por mensagens vindas do patch de controle.

A cadeia GEM é declarativa: cada frame é redesenhado com os valores atuais dos atributos. Isso é análogo ao draw() do p5.js, que veremos mais adiante.

Objetos essenciais do GEM

[gemwin]
Cria e controla a janela de renderização. Recebe mensagens create e destroy.
[gemhead]
Ponto de entrada do pipeline GEM. Tudo conectado abaixo é renderizado a cada frame.
[sphere]
Geometria 3D básica. Aceita raio como argumento e atributos de cor, posição e rotação.
[translateXYZ]
Move a geometria no espaço 3D. Recebe valores X, Y, Z na entrada.
[color]
Define cor RGBA da geometria. Valores de 0 a 1 para cada canal.
[pix_video]
Captura entrada de vídeo da câmera — permite usar o feed ao vivo como textura ou processá-lo em tempo real.
1
Criar [gemwin] e enviar a mensagem create — a janela de renderização abre
2
Montar a cadeia: [gemhead] → [sphere 0.5] — uma esfera aparece no centro da janela
3
Inserir [translateXYZ] entre gemhead e sphere — conectar as saídas X e Y do [mousestate] normalizadas à entrada do translate
4
Conectar a amplitude do microfone [env~] ao raio da esfera — a forma pulsa com o som ambiente
5
Atividade: o mouse move a esfera, o microfone controla o tamanho, o teclado muda a cor via [color]

Introdução ao Arduino

Arduino é uma plataforma de prototipagem eletrônica baseada em microcontrolador — um computador em miniatura dedicado a ler entradas físicas e controlar saídas elétricas. É o ponto de entrada mais comum para a interface analógico-digital.

Conceito
O que é um microcontrolador

Ao contrário de um computador de propósito geral, um microcontrolador executa um único programa em loop contínuo — sem sistema operacional, sem múltiplos processos. Isso o torna previsível, rápido para responder a entradas físicas e muito mais simples de programar para tarefas de tempo real.

O Arduino abstrai o hardware com uma linguagem baseada em C++, tornando acessível o controle de pinos digitais, leitura de sensores analógicos e comunicação serial.

Anatomia do Arduino Uno

  • Pinos digitais (0–13) — leitura ou escrita de valores binários: 0V (LOW) ou 5V (HIGH). Os pinos com ~ suportam PWM — simulação de valores analógicos por pulso.
  • Pinos analógicos (A0–A5) — leitura de tensão entre 0 e 5V, convertida para valores de 0 a 1023 (10 bits de resolução).
  • 5V e GND — alimentação e terra para sensores e componentes externos.
  • USB / Serial — comunicação com o computador. É por aqui que o Firmata transmite dados para o PD.

Estrutura básica de um programa Arduino

// setup() roda uma vez ao ligar
void setup() {
  Serial.begin(9600);
  pinMode(13, OUTPUT);
}

// loop() roda continuamente
void loop() {
  int valor = analogRead(A0);
  Serial.println(valor);
  delay(10);
}

Subindo o firmware Firmata

Firmata é um protocolo que transforma o Arduino em um dispositivo de I/O controlado pelo computador — em vez de executar um programa próprio, ele responde a comandos vindos do PD via porta serial. Para isso, o Arduino precisa receber o firmware Firmata uma única vez.

Conceito
Firmata — inversão de controle

No uso convencional do Arduino, o programa roda no microcontrolador e o computador é passivo. Com Firmata, a lógica fica no computador — no caso, no patch PD — e o Arduino vira um periférico inteligente: lê sensores e aciona saídas sob comando externo. Essa inversão é o que torna possível integrar hardware físico a um patch audiovisual em tempo real.

Passos para subir o Firmata

1
Baixar e instalar a Arduino IDE: arduino.cc/en/software ↗
2
Conectar o Arduino ao computador via USB — confirmar que a porta serial aparece em Tools → Port
3
Abrir o firmware: File → Examples → Firmata → StandardFirmata
4
Selecionar a placa correta em Tools → Board — para Arduino Uno, selecionar Arduino Uno
5
Clicar em Upload (→) — aguardar a confirmação "Done uploading" no console. O Arduino agora fala Firmata.

Integração de hardware com Pduino

Com o Firmata no Arduino e a biblioteca Pduino instalada no PD, os dois ambientes se comunicam pela porta serial. Dados de sensores físicos entram no patch como mensagens — o mesmo tipo de dado que já vimos vindo do mouse e do teclado.

Objetos do Pduino

[arduino]
Objeto central da biblioteca. Estabelece a conexão com o Arduino via porta serial e expõe os dados dos pinos como saídas.
[arduino-analog]
Leitura dos pinos analógicos (A0–A5). Retorna valores de 0 a 1023 em tempo real.
[arduino-digital]
Leitura e escrita de pinos digitais. Recebe ou envia 0 ou 1.

Conectando ao PD

1
Criar [arduino] no patch. Na mensagem de abertura da porta, especificar o caminho serial: ex. [open /dev/ttyUSB0( no Linux/Mac ou [open COM3( no Windows
2
Enviar a mensagem de abertura via bang — observar no console se a conexão foi estabelecida
3
Criar [arduino-analog 0] para ler o pino A0 — conectar saída a uma caixa numérica e variar o sensor (potenciômetro ou LDR)
4
Normalizar o valor: [/ 1023] — resultado de 0 a 1, pronto para mapear a qualquer parâmetro do patch
5
Atividade final: sensor físico controlando frequência do oscilador e posição da esfera no GEM — o loop analógico-digital completo em um único patch
O que aconteceu: um valor físico — resistência de um potenciômetro ou incidência de luz num LDR — percorre o caminho: sensor → Arduino → Firmata → porta serial → Pduino → mensagem PD → parâmetro de síntese sonora e visual. Isso é a interface analógico-digital.
